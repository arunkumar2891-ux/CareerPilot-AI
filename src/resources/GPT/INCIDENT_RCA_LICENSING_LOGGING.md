## Executive Summary

During quarter-end/year-end business processing, the Licensing team reported that application logs from several SnapLogic pipelines were no longer visible in the observability platform. As these pipelines support business-critical processes, the loss of observability significantly impacted the team's ability to monitor executions and troubleshoot issues, resulting in an escalation.

The incident was caused by the decommissioning of legacy Datadog API credentials, which exposed that these pipelines were still using a legacy custom logging implementation instead of the enterprise common logging framework.

**Resolution:** Updated the logging pipeline to publish log events to the enterprise Pub/Sub topic consumed by Chronosphere, restoring observability and unblocking the business immediately.

## Root Cause Analysis

### Primary Root Cause

The affected Licensing pipelines were using a **legacy custom logging implementation** that published application logs directly to the **Datadog REST API**.

### Contributing Factors

1. **Infrastructure Decommissioning:** As part of the enterprise observability migration, the legacy Datadog logging endpoint and API credentials were decommissioned
2. **Incomplete Migration:** These pipelines had not yet migrated to the enterprise common logging framework used by newer SnapLogic implementations
3. **Architectural Inconsistency:** Unlike newer integrations that leverage the common logging framework, these pipelines maintained a custom logging approach
4. **Timing:** The decommissioning occurred during quarter-end/year-end processing, amplifying the business impact

### Technical Details

**Before Decommissioning:**
- Licensing pipelines executed business logic successfully
- Logging pipeline made direct REST POST calls to Datadog API
- Application logs were published to Datadog and visible to the team

**After Decommissioning:**
- Licensing pipelines continued to execute successfully (business logic unaffected)
- Logging pipeline attempted to make REST POST calls to the decommissioned Datadog API
- API calls failed silently (no error propagation to business logic)
- Application logs were generated but never reached the observability platform
- Complete loss of observability for these integrations

## Lessons Learned

### Key Insights

1. **Importance of Standards Adoption**
   - Adopting enterprise platform standards before infrastructure decommissioning is critical
   - Custom implementations create technical debt and operational risk

2. **Migration Planning**
   - Infrastructure decommissioning should be coordinated with application migration
   - Legacy implementations should be identified and migrated proactively

3. **Observability as Critical Infrastructure**
   - Loss of observability can be as impactful as loss of business logic
   - Observability infrastructure should be treated with same rigor as business logic

4. **Timing Sensitivity**
   - Quarter-end/year-end processing amplifies the impact of any infrastructure issues
   - Critical infrastructure changes should be avoided during high-impact business periods

### Preventive Measures

1. **Standardization**
   - Enforce adoption of enterprise common logging framework for all new integrations
   - Migrate existing custom implementations to enterprise framework

2. **Monitoring**
   - Implement health checks for logging pipeline
   - Alert on logging failures before they impact observability

3. **Planning**
   - Coordinate infrastructure decommissioning with application migration timelines
   - Identify and migrate legacy implementations before decommissioning

4. **Documentation**
   - Document all custom implementations and their dependencies
   - Maintain inventory of infrastructure dependencies
