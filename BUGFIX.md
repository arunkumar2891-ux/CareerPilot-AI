## Investigation Workflow

Follow this workflow when fixing a bug:

### 1. Start with identified files

Read the files listed in "Relevant Files" above. Do NOT search the whole repository.

### 2. Trace the execution path

Follow the call chain from the symptom's entry point:
- UI event → page component → service call → Edge Function → database/external API
- Use imports and function calls to trace, not grep.

### 3. Identify root cause

Determine the exact line(s) causing the issue. Confirm with evidence (logs, data, type mismatches).

### 4. Stay scoped

Do NOT search outside the identified files unless an import or dependency explicitly requires it.

### 5. Expand only when necessary

If the root cause is not in the identified files, expand to the directly imported modules only.

### 6. Make the smallest viable fix

- Fix the root cause, not symptoms.
- Change the minimum number of files/lines.
- Do not refactor unrelated code.
- Preserve existing API contracts.

### 7. Validate

- Run `npm run typecheck` for type errors.
- Run `npm run lint` for lint errors.
- Test the specific reproduction steps.
- Confirm no regressions in related features.

### 8. Report

After fixing, document in `BUG_LOG.md`:
- Root cause
- Files changed
- Summary of fix
- Validation performed
- Any remaining risks
